Application Info
What will the API do?
The E-Commerce API will provide a complete backend solution for an online store. It will allow users to browse products, create accounts, place orders, leave reviews, and manage their profiles. The API will support product management, order processing, user authentication, and review functionality.

How will your API utilize a login system?
The API will use OAuth 2.0 for user authentication. Users will be able to log in using their credentials, and the system will issue JWT tokens that will be used to authenticate subsequent API requests. Protected routes will require a valid token in the Authorization header.

What database will you use?
MongoDB will be used as the database. It's a NoSQL database that fits well with the document-based structure of our data and allows for flexible schema evolution.

How will the data be stored in your database?
Data will be stored in 5 collections:
- Users: username, email, password (hashed), firstName, lastName, address, phone, role
- Products: name, description, price, category, stock, sku, imageUrl, brand
- Orders: userId, items (array of product IDs and quantities), totalAmount, status, shippingAddress, paymentMethod, orderDate
- Reviews: userId, productId, rating, comment, reviewDate
- Categories: name, description

How would a frontend be able to manage authentication state based on the data you provide?
The API will return a JWT token upon successful login. The frontend will store this token (typically in localStorage or a cookie) and include it in the Authorization header for all subsequent requests to protected endpoints. The token will contain user information and expiration time.

What pieces of data in your app will need to be secured? How will you demonstrate web security principles in the development of this app?
- User passwords will be hashed using bcrypt before storage
- JWT tokens will be used for authentication with expiration
- Sensitive data (passwords, payment info) will never be exposed in API responses
- HTTPS will be enforced in production
- Input validation will be implemented on all endpoints
- Rate limiting will be implemented to prevent abuse
- CORS will be properly configured

What file structure and program architecture will you use for this project (how will you organize your node project)? Why?
The project will follow MVC architecture:
- models/: Mongoose schemas for each collection
- routes/: Express route handlers for each collection
- controllers/: Business logic (optional, can be combined with routes)
- middleware/: Authentication middleware, error handling
- config/: Database configuration, environment variables
- tests/: Unit tests for GET routes
- server.js: Main application entry point

This structure promotes separation of concerns, maintainability, and scalability.

Potential Risks and Risk Mitigation Techniques
What are the risks involved with you being able to finish this project in a timely manner?
- OAuth implementation complexity may take longer than expected
- Managing 5 collections with relationships may be challenging
- Unit testing for all GET routes may be time-consuming
- Integration of authentication with all protected routes
- Time management with other coursework

How will you mitigate or overcome these risks?
- Start OAuth implementation early in Week 5
- Use existing OAuth libraries (Passport.js) to simplify implementation
- Plan database relationships carefully before implementation
- Write unit tests incrementally as each route is completed
- Create a detailed schedule and stick to it
- Start with simpler collections (Categories) before complex ones (Orders)
- Use the Week 3 project as a foundation for Products and Categories
